3. BACKEND (api/)
--------------------------------------------------------------------------------
Contrato versionado: /api/v1, envelope { data, meta } con correlationId.

Archivos nuevos en Fase 4:
  api/app/auth.py
    - Roles: superadmin, admin, coordinador, docente, estudiante, analista,
      mle, auditor.
    - require(permiso): dependencia FastAPI con 403 auditada.
    - require_signature(): la firma docente debe coincidir con el actor.
    - RBAC_ENFORCE (default 1) y DEMO_DEFAULT_ROLE (default estudiante).
  api/app/services/audit.py
    - add_audit() y audit_denied() con role, actor_id, tenant_id, method,
      path, ip_address y status (success/denied).
  api/app/services/settings.py
    - Configuracion institucional persistida con el patron storage.py.

Endpoints relevantes:
  GET  /health                       -> auth=demo-header-rbac, rbacEnforced,
                                        tenantId, storage=memory-demo
  GET/POST /api/v1/audit/logs        -> requiere audit:read / audit:write
  GET/PUT  /api/v1/settings          -> requiere settings:view / settings:edit
  GET/PUT  /api/v1/settings/preferences    -> preferencias por actor
  GET/PUT  /api/v1/notification-preferences -> alias legacy actor-scoped
  GET/POST /api/v1/courses           -> RBAC (courses:view / courses:edit)
  POST     /api/v1/courses/{id}/enroll     -> courses:enroll
  GET/POST /api/v1/learning-paths    -> progreso ABAC por actor
  GET/POST /api/v1/assessments, /api/v1/submissions -> firma docente ABAC
  GET/POST /api/v1/sandbox/attempts  -> analisis estatico, sin ejecucion

Persistencia:
  - Sin credenciales Supabase: almacenamiento en memoria (DEMO).
  - api/supabase/schema.sql preparado con certificate, audit_logs enriquecido,
    settings, notification_preferences, submissions y sandbox_attempts.
  - RLS queda COMENTADO: "rlsEnabled" es informativo, nunca activa RLS real.

Variables de entorno nuevas (api/.env.example):
  RBAC_ENFORCE=1
  DEMO_DEFAULT_ROLE=estudiante
  TENANT_ID=org-ute-peru-2026

6. LIMITACIONES IMPORTANTES (NO CAMBIAR)
--------------------------------------------------------------------------------
  - No hay OIDC/JWT real. La autoridad backend es DEMO de headers
    X-Actor/X-Role. No presentarla como seguridad de produccion.
  - Sin credenciales de Supabase: storage=memory-demo, la auditoria se
    pierde al reiniciar el servicio.
  - "settings.rlsEnabled" es informativo; no activa Row Level Security.
  - La decision oficial del artefacto MTL permanece: DEMO: no publicar.
    El modelo nunca publica nota oficial.
  - El frontend RBAC es solo UX; la API revalida permisos en servidor.
  - No publicar metricas falsas ni etiquetas de produccion.
  - Backend sin PyTorch, Redis, Celery ni MLflow. REST con urllib.
